# TKT-034 - Add dual language vectors and technical identifier normalization

**Epic:** [Epic H: Robust lightweight search](epics/EPIC-H.md)
**Milestone:** [M8: Robust lightweight search](milestones/M8.md)
**Labels:** `search`, `postgresql`, `migration`, `technical-terms`, `epic-h`, `m8`
**Dependency links:** [TKT-033](TKT-033.md)
**Design link:** [docs/DESIGN.md section 21](../docs/DESIGN.md#21-search-quality-design)
**Backlog link:** [tickets/README.md](README.md)

**Goal:** Combine exact technical-term behavior with ordinary English word-form matching using only native PostgreSQL indexes.

**Dependencies:** TKT-033

**Scope:**

- Add a new numbered migration for separate `simple` and `english` search vectors and GIN indexes.
- Preserve direct technical-vector matches as the highest-priority lexical class.
- Query the English vector for useful stemmed-language matches.
- Add a bounded indexing normalizer for codes such as `A-12`, `A12`, and `A 12`.
- Keep original semantic text untouched for display and snippets.
- Reindex existing local documents safely and document the main-app migration requirement.
- Record index size and import/query timing before and after the migration.

**Out of scope:** `pg_trgm`, custom PostgreSQL dictionaries, unbounded code variants, and fuzzy scanning.

**Acceptance criteria:**

- Technical identifiers remain directly searchable in their source form.
- Configured deterministic identifier variants resolve to the same content.
- Useful English word forms match without lowering direct-match priority.
- Both normal query paths use GIN indexes.
- Existing documents are reindexed without reparsing their PDFs.

**Verification:** Migration tests, technical-code matrix, stemming fixtures, `EXPLAIN` review, and before/after size and latency report.
