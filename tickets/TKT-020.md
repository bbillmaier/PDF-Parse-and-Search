# TKT-020 - Normalize document-family glyphs and list markers

**Epic:** [Epic C: Text and semantic extraction](epics/EPIC-C.md)
**Milestone:** [M3: Recover readable semantic text](milestones/M3.md)
**Labels:** `fonts`, `text-normalization`, `lists`, `testing`, `epic-c`, `m3`
**Dependency links:** [TKT-010](TKT-010.md), [TKT-013](TKT-013.md)
**Design link:** [docs/DESIGN.md](../docs/DESIGN.md)
**Backlog link:** [docs/TICKETS.md](../docs/TICKETS.md)

**Goal:** Convert the remaining source-specific symbol glyphs and malformed list markers into clean Unicode and semantic list content without changing ordinary prose or unrelated private-use characters.

**Dependencies:** TKT-010, TKT-013

**Scope:**

- Retain enough resolved-font identity to distinguish Wingdings-derived fonts, including the PDF `/BaseFont` name after subset-prefix normalization.
- For Wingdings-derived fonts only, map `U+F0A7` to `U+25AA` (`▪`, BLACK SMALL SQUARE) and `U+F0A8` to `U+2610` (`☐`, BALLOT BOX).
- Sanitize decoded PDF text strings and alternate text by removing trailing NUL (`U+0000`) code units. Preserve replacement characters and other unknown glyph evidence so decoding failures remain visible.
- When a tagged `LI` has no explicit `Lbl`, remove a leading literal lowercase `o` and following whitespace from its first paragraph while preserving the semantic unordered-list item.
- Add focused unit tests and AFQTP sample-corpus regression coverage, then update affected snapshots.

**Guardrails:**

- Do not globally replace private-use characters. Symbol interpretation must be conditional on a verified Wingdings-derived font.
- Do not strip a leading `o` outside a tagged list item, or when an explicit list label exists.
- Do not remove `U+FFFD` or broadly suppress unknown-glyph warnings.
- Keep normalization inside the portable library; do not add application-specific post-processing or external dependencies.

**Out of scope:**

- General support for every symbol font.
- Font styling or visual font preservation.
- TOC ordering, numbered-paragraph reconstruction, table-cell splitting, or image lifecycle changes; those are already handled separately.
- OCR or raster-only text recognition.

**Acceptance criteria:**

- The AFQTP public model contains no `U+F0A7` or `U+F0A8`, and contains the expected `▪` and `☐` characters instead.
- The page-one figure alternate text contains no NUL and matches the clean source description.
- Affected nested list items no longer begin with the literal marker `o `, while ordinary prose beginning with `o` is unchanged.
- Unrelated private-use characters remain untouched unless decoded by an existing font map.
- Existing warning behavior and the dependency-free worker API remain intact.
- Unit tests, full integration tests, type checking, and the production build pass.

**Verification:**

- `npm run test:unit`
- `npm run test:integration`
- `npm run typecheck:test`
- `npm run build`
