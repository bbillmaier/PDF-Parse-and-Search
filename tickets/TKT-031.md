# TKT-031 - Implement deterministic multi-signal search ranking

**Epic:** [Epic H: Robust lightweight search](epics/EPIC-H.md)
**Milestone:** [M8: Robust lightweight search](milestones/M8.md)
**Labels:** `search`, `ranking`, `postgresql`, `testing`, `epic-h`, `m8`
**Dependency links:** [TKT-030](TKT-030.md)
**Design link:** [docs/DESIGN.md section 21](../docs/DESIGN.md#21-search-quality-design)
**Backlog link:** [tickets/README.md](README.md)

**Goal:** Rank direct, complete, structurally important matches ahead of repetitive body-text matches using documented deterministic signals.

**Dependencies:** TKT-030

**Scope:**

- Centralize ranking constants and score composition in one server module.
- Weight titles/headings above table context and ordinary body text.
- Add direct phrase, ordered-near, and distinct-term coverage boosts.
- Apply length normalization so large paragraphs do not win by repetition alone.
- Rank prefix, synonym, and future fallback match classes below direct matches.
- Add stable tie-breaking by document, page, and block identity.
- Expose development-only score components sufficient to explain ranking tests.

**Out of scope:** User-personalized ranking, behavioral analytics, embeddings, and typo generation.

**Acceptance criteria:**

- Equivalent heading matches rank above body-only matches.
- Complete phrase matches rank above scattered occurrences of the same terms.
- Repetition in a very long block does not overwhelm a concise strong match.
- Repeated executions against unchanged data return the same ordering.
- Ranking SQL remains parameterized and uses indexed candidate selection.

**Verification:** Ranking fixtures, corpus relevance assertions, deterministic-order tests, and representative `EXPLAIN` review.
