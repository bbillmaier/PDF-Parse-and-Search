# TKT-036 - Improve display-title selection and searchable metadata

**Epic:** [Epic H: Robust lightweight search](epics/EPIC-H.md)
**Milestone:** [M8: Robust lightweight search](milestones/M8.md)
**Labels:** `metadata`, `titles`, `search`, `parser`, `integration`, `epic-h`, `m8`
**Dependency links:** [TKT-022](TKT-022.md)
**Design link:** [docs/DESIGN.md section 21](../docs/DESIGN.md#21-search-quality-design)
**Backlog link:** [tickets/README.md](README.md)

**Goal:** Choose credible document titles and preserve searchable metadata so boilerplate such as `BY ORDER OF THE` does not become the primary library label.

**Dependencies:** TKT-022

**Scope:**

- Preserve raw PDF metadata separately from the selected display title.
- Support explicit host/admin title, credible metadata, first-page semantic heading, and cleaned-filename priority.
- Add conservative document-family boilerplate rejection and confidence/source metadata.
- Allow the host to override the display title without reparsing the PDF.
- Persist and index the selected title plus useful stable document metadata.
- Rebuild affected search records/index rows after a title override.
- Cover the supplied corpus, including the current `BY ORDER OF THE` failure.

**Out of scope:** General document classification, OCR, department-specific private data, and AI title generation.

**Acceptance criteria:**

- No supplied sample uses known cover-page boilerplate as its display title when a better candidate exists.
- Raw metadata remains inspectable and is never silently destroyed.
- Low-confidence selection falls back to a cleaned filename.
- A title override updates library/search display without PDF re-extraction.
- Repeated parsing produces the same inferred title and confidence.

**Verification:** Title-candidate unit matrix, real-corpus assertions, override lifecycle test, and search reindex test.
