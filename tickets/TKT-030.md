# TKT-030 - Produce concise match-centered snippets and grouped results

**Epic:** [Epic H: Robust lightweight search](epics/EPIC-H.md)
**Milestone:** [M8: Robust lightweight search](milestones/M8.md)
**Labels:** `search`, `snippets`, `ranking`, `api`, `ui`, `epic-h`, `m8`
**Dependency links:** [TKT-027](TKT-027.md)
**Design link:** [docs/DESIGN.md section 21](../docs/DESIGN.md#21-search-quality-design)
**Backlog link:** [tickets/README.md](README.md)

**Goal:** Replace oversized block text in search results with safe, concise excerpts and prevent one long document from dominating the result page.

**Dependencies:** TKT-027

**Scope:**

- Generate a bounded plain-text excerpt around the best direct match.
- Normalize display whitespace without changing stored source content.
- Return matched terms or ranges separately from snippet text.
- Escape text in React before applying highlight elements.
- Group adjacent same-section matches when they represent one answer context.
- Enforce configurable per-document and total result caps.
- Preserve document, heading path, block, section, and PDF page navigation.

**Out of scope:** New query syntax, stemming, fuzzy matching, synonyms, and AI summaries.

**Acceptance criteria:**

- Search never returns an entire multi-thousand-character paragraph as its default snippet.
- Every snippet contains a relevant match and bounded surrounding context.
- Grouping does not hide distinct matches in different sections or pages.
- One document cannot consume every visible result when other documents match.
- Hostile extracted text cannot inject HTML through highlighting.

**Verification:** Unit tests for boundaries/highlighting, API result tests, and multi-document UI tests.
