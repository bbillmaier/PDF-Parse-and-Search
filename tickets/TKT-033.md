# TKT-033 - Add prefix matching and progressive partial-result fallback

**Epic:** [Epic H: Robust lightweight search](epics/EPIC-H.md)
**Milestone:** [M8: Robust lightweight search](milestones/M8.md)
**Labels:** `search`, `fallback`, `prefix`, `postgresql`, `performance`, `epic-h`, `m8`
**Dependency links:** [TKT-032](TKT-032.md)
**Design link:** [docs/DESIGN.md section 21](../docs/DESIGN.md#21-search-quality-design)
**Backlog link:** [tickets/README.md](README.md)

**Goal:** Return useful results for incomplete or overly strict queries while keeping direct complete matches first and server work bounded.

**Dependencies:** TKT-032

**Scope:**

- Add safe final-term prefix matching for incomplete user input.
- Construct prefix queries only from validated server-tokenized terms.
- Run a bounded partial-term fallback only when strict results are insufficient.
- Score by directness and distinct-term coverage; clearly demote partial results.
- Report the match strategy used so the UI can explain broadened results.
- Cap prefix expansion, fallback terms, candidates, per-document results, and total results.
- Cancel or ignore stale frontend requests during rapid typing.

**Out of scope:** Substring scans, leading-wildcard queries, edit-distance matching, and PostgreSQL extensions.

**Acceptance criteria:**

- `inspect` can find relevant `inspection` content through an indexed prefix path.
- A strict all-term result always ranks above a partial fallback result.
- The UI indicates when results were broadened.
- Raw user text never becomes executable `tsquery` syntax.
- Synthetic scale tests show bounded query plans and latency.

**Verification:** Strict/prefix/partial query tests, stale-request UI tests, `EXPLAIN` assertions, and thousands-document benchmark records.
