# TKT-022 - Generate portable search records from semantic documents

**Epic:** [Epic F: Searchable semantic foundation](epics/EPIC-F.md)
**Milestone:** [M6: Searchable semantic foundation](milestones/M6.md)
**Labels:** `search-records`, `semantic-model`, `serialization`, `tables`, `testing`, `epic-f`, `m6`
**Dependency links:** [TKT-021](TKT-021.md)
**Design link:** [docs/DESIGN.md](../docs/DESIGN.md)
**Backlog link:** [docs/SEARCH_TICKETS.md](../docs/SEARCH_TICKETS.md)

**Goal:** Convert a semantic document into plain, serializable search records without coupling the extractor to PostgreSQL or the host application.

**Dependencies:** TKT-021

**Scope:**

- Define and export `DocumentSearchRecord` and related public types.
- Produce records for headings, paragraphs, list items, table cells, and figure captions.
- Include document ID/title, section ID, block ID, heading, heading path, page number, block type, searchable text, table header, and row header when known.
- Preserve enough table context for a result to make sense without rendering the entire table.
- Exclude empty, artifact-only, and non-searchable blocks.
- Keep output deterministic, structured-cloneable, and JSON-serializable.
- Decide and document whether records are returned with parse results or built through a public pure helper; do not expose library internals either way.

**Out of scope:** Stemming, SQL, ranking, snippets, database writes, and UI.

**Acceptance criteria:**

- Every record resolves to an existing semantic block and rendered anchor.
- Heading paths accurately describe nested section context.
- Table records contain available row/column context without duplicating an entire table into each cell.
- Repeated extraction produces byte-equivalent JSON records.
- Corpus tests demonstrate useful records from prose, lists, and tables.
- Record generation adds no third-party runtime dependency.

**Verification:** Pure unit tests, JSON round-trip tests, and full-corpus integration snapshots.
