# TKT-032 - Support safe web-style search syntax and exact phrases

**Epic:** [Epic H: Robust lightweight search](epics/EPIC-H.md)
**Milestone:** [M8: Robust lightweight search](milestones/M8.md)
**Labels:** `search`, `query-parser`, `postgresql`, `security`, `epic-h`, `m8`
**Dependency links:** [TKT-031](TKT-031.md)
**Design link:** [docs/DESIGN.md section 21](../docs/DESIGN.md#21-search-quality-design)
**Backlog link:** [tickets/README.md](README.md)

**Goal:** Let users express quoted phrases, alternatives, and exclusions without exposing raw PostgreSQL query syntax.

**Dependencies:** TKT-031

**Scope:**

- Use parameterized `websearch_to_tsquery` for supported web-style syntax.
- Support quoted phrases, `OR`, and excluded terms.
- Preserve a normalized query representation for snippets and diagnostics.
- Define behavior for unmatched quotes, punctuation-only input, repeated operators, and technical codes.
- Bound query length and normalized term count.
- Return a controlled validation response for unusable queries.
- Add brief UI help/examples without turning the search box into an advanced form.

**Out of scope:** Arbitrary `to_tsquery` input, regex search, field-query syntax, fuzzy matching, and natural-language answers.

**Acceptance criteria:**

- `"engine inspection"`, `engine OR motor`, and `inspection -aircraft` behave predictably.
- Injection-looking input cannot alter SQL or escape the query parameter.
- Empty and punctuation-only input does not execute an expensive database query.
- Existing ordinary multiword searches remain supported.
- Exact phrase results receive the ranking signal defined by TKT-031.

**Verification:** Query parser matrix, hostile-input API tests, PostgreSQL integration tests, and UI help-state tests.
