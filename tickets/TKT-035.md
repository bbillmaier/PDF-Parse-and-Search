# TKT-035 - Add bounded domain synonyms and typo suggestions

**Epic:** [Epic H: Robust lightweight search](epics/EPIC-H.md)
**Milestone:** [M8: Robust lightweight search](milestones/M8.md)
**Labels:** `search`, `synonyms`, `spelling`, `configuration`, `epic-h`, `m8`
**Dependency links:** [TKT-034](TKT-034.md)
**Design link:** [docs/DESIGN.md section 21](../docs/DESIGN.md#21-search-quality-design)
**Backlog link:** [tickets/README.md](README.md)

**Goal:** Recover from domain terminology differences and common misspellings without extensions or full-content fuzzy scans.

**Dependencies:** TKT-034

**Scope:**

- Add a small versioned domain-synonym configuration with directional expansion.
- Deduplicate and cap synonym-expanded terms and expose expansion diagnostics.
- Build/maintain a compact vocabulary from titles, headings, technical tokens, and useful indexed terms.
- Run bounded edit-distance suggestions only for empty or weak normal results.
- Filter typo candidates by length and prefix characteristics before edit distance.
- Present corrections as explicit suggestions or clearly labeled corrected searches.
- Rank direct results above synonym-only and corrected-term results.

**Out of scope:** Automatic synonym discovery, unrestricted fuzzy search, `pg_trgm`, and silent query rewriting.

**Acceptance criteria:**

- Configured synonyms find expected domain content without changing stored text.
- `inspeciton` can suggest `inspection` after an unsuccessful direct search.
- Correctly spelled successful queries do not pay the typo-candidate cost.
- Expansion and candidate counts remain within documented limits.
- The UI makes every correction or expansion understandable to the user.

**Verification:** Synonym configuration tests, typo candidate/limit tests, ranking assertions, no-result UI tests, and performance measurements.
